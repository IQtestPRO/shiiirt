# Design System for Conversion

## Objetivo
Criar componentes e tokens que preservam consistência, acessibilidade, velocidade e padrões de conversão em escala.

## Quando usar
- Múltiplas landing pages
- Equipe criando páginas sem padrão
- CTAs inconsistentes
- Redesign frequente
- Site com stack moderna

## Como aplicar
1. Definir tokens de cor/tipo/spacing.
2. Criar componentes de conversão.
3. Documentar estados e variantes.
4. Adicionar exemplos.
5. Validar acessibilidade.
6. Versionar mudanças.

## Checklist de implementação
- [ ] Tokens semânticos
- [ ] Componentes mobile-first
- [ ] Props tipadas
- [ ] Estados acessíveis
- [ ] Exemplos de uso
- [ ] Sem dependências desnecessárias
- [ ] Versionamento

## Automação possível
Gerar componentes React/Tailwind, lint de tokens, previews, testes visuais e templates por tipo de página.

## Inputs necessários
- Marca
- Stack
- Páginas alvo
- Tokens
- Componentes existentes
- Métricas

## Outputs esperados
- Biblioteca de componentes
- Templates
- Guidelines
- Checklist QA
- Roadmap

## Métricas impactadas
- build_speed
- design_consistency
- conversion_rate
- a11y_score
- defect_rate

## Exemplos práticos
- SaaS B2B: Sistema com HeroSection, PricingTable, FAQ e LeadCaptureForm.
- E-commerce: ProductFeatureGrid, SocialProof e CheckoutSummary reutilizáveis.
- Infoproduto/curso online: CTASection, TestimonialGrid e ConversionFooter para lançamentos.

## Prompts auxiliares
- Crie um design system de conversão em React/Tailwind para este nicho.
- Audite estes componentes por consistência, acessibilidade e CRO.
